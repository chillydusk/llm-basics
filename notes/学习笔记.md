# 我的学习笔记 · 2026-10-14

## 一、Tool Calling：模型动嘴，我动手

今天搞懂了 tool calling 的核心：**模型自己不能执行任何东西**。

它在云端，没有我的时钟、没有我的文件、没有我的网络。它唯一能做的是**输出一段文字**，
说"请调用某个工具，参数是这些"。真正干活的是**我的代码** ——
我负责把参数解码（`json.loads`）、执行函数、再把结果塞回 `messages` 里递回去。

整个往返是六步：发请求 → 模型说要工具（`finish_reason = tool_calls`）→ 我执行 →
把结果包成 `role: "tool"` 消息回传 → 模型拿到结果 → 用人话作答（`finish_reason = stop`）。

**一句话记住：模型负责"决策"和"说话"，我负责"执行"。**

## 二、今天踩的两个坑

**坑一：工具调用写死了。** 模型要调 `calculate`，我却执行了 `get_time()`，
结果把时间戳当成"1234+5678 的和"回传。模型不干，又找我要了一次工具。
教训：**不能写死，要按 `tc.function.name` 查一张表来分发**。

**坑二：`arguments` 是字符串，不是字典。** 它外面还套着一层引号 ——
因为它是跨进程传过来的文本。必须先 `json.loads` 才能用，
否则 `func(**args)` 会报 `TypeError: must be a mapping, not str`。

## 三、自修复：错误不是终点，是下一轮的输入

我手动喂了一个坏参数（`a = "你好"`），用 pydantic 校验拦住，
然后**把错误信息当成"工具的执行结果"回传给了模型**。

模型拿到错误后，**回头翻了对话历史**，自己把参数改对（改回 `1234`）**又重试了一次**。

这就是"自修复"。也是为什么 Agent 需要循环 ——
它想转第二圈的时候，我的单轮代码接不住。
