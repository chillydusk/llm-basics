# 怎么把 README 顶部那张图换成真动图

现在 README 顶部是 `docs/demo.svg` —— 一个字一个字排出来的终端实录，
优点是**不用录屏、GitHub 直接渲染、永不失效**。

缺点是它不会动。动图的说服力还是更强，值得花 10 分钟换掉。

---

## 一、录

**工具**（Windows，都免费）：

| 工具 | 地址 | 说明 |
|---|---|---|
| ScreenToGif | https://www.screentogif.com/ | 推荐。录完能逐帧删、能压体积 |
| LICEcap | https://www.cockos.com/licecap/ | 更轻，但编辑能力弱 |

**录制前**：

1. 终端字号调到 **16–18 号**（GIF 会被压缩，字小了糊）
2. 终端宽度调到 **100 列左右**，别让它换行
3. 清屏（`clear`），让画面从空白开始
4. 窗口背景用深色 —— 和现在的 SVG 保持一致

**录制内容**（15–30 秒最好，太长没人看完）：

```bash
# Git Bash，项目根目录
uv run study-assistant ask "我的笔记里说索引为什么用 B+ 树？按笔记回答，并注明来源。"
```

录到这里就够了：输入 → `⚙️ search_notes(...)` → 带引用的答案 → 每轮花费。

**别录**：装依赖、`uv sync` 刷屏、长思考过程。

---

## 二、存

放到 `docs/demo.gif`。

体积控制在 **5 MB 以内**（GitHub 超过 10 MB 会拒绝渲染）。
ScreenToGif 导出时：帧率 10 fps、调色板 256 色、删掉静止帧，基本都能压到 2–3 MB。

---

## 三、换

把 `README.md` 第 6 行改掉：

```markdown
![终端实录](docs/demo.svg)
```

改成：

```markdown
![终端实录](docs/demo.gif)
```

`docs/demo.svg` 可以留着当备份，也可以删掉。

---

## 四、检查

推之前**在本地把 README 预览一遍**（VS Code 里 `Ctrl+Shift+V`），确认：

- [ ] 图能显示，不是裂图
- [ ] 图里的字能看清
- [ ] 图里的路径 / 命令和现在的代码一致（改过代码要重录）

---

## 附：只想要静态图的话

`docs/demo.svg` 已经能用了，什么都不用做。
它的内容是 2026-10-26 那一次真实运行的输出，命令和结果都能复现。
